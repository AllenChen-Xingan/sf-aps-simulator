# Reproducibility report

This document states how the results in `results/` are regenerated from the code in `code/`, which checks were run in a clean environment, how long each step takes, and which outputs cannot be reproduced bit for bit. Development, testing and analysis are documented in `docs/TRACE.md` following Grimm et al. (2014); the experimental design is in `docs/experiment-protocol.md`.

| `code/data/inputs.json` | `f37b2885f630e8fe94d4ec9a690968e35b1ab7960f0aef5d141ff1a2218f0401` |
| Combined model fingerprint | `e0f4869e2c32e15f2f3b905a242bcbaa09f7102cf6aaf151acf3e2ac11dff18f` |

The combined fingerprint is the SHA-256 of the three hexadecimal digests above, joined in that order by newline characters (`code/final_export.py`, `code/e3_variant.py`). It is written into `results/e3-variant/summary.json` and `results/web/meta.json`, so each of these result files identifies the model that produced it. Checksums of every file in the package are listed in `SHA256SUMS`.

The clean environment was created with `python3.14 -m venv` and populated only from the lock file. `pip check` reported no broken requirements and `pip freeze` matched the lock file line for line. Installation took 12–15 s with a warm package cache; a cold installation downloads 39 wheels and takes longer, depending on the network.

The simulation itself uses only the Python standard library and NumPy. The other packages are used for sampling and analysis (SALib, EMA Workbench, scikit-learn, pandas) and for figures (Matplotlib).

## 3. Contents and omitted files

The package contains all code, the two model inputs (`code/data/inputs.json`, `code/data/pending76-crashes.csv`), the two inputs of the E0 baseline check (`code/data/e0-baseline/`), and every summary output. Raw outputs are omitted because of their size; each is regenerated by the command shown (run inside `code/`).

| Omitted file | Size | Regenerated by |
|---|---|---|
| `e1-fit/accepted-sets.json` (parameter combinations accepted by historical screening) | 41 MB | `python -I experiments.py e1` |
| `e3-pathways/runs.csv.gz` (one row per pathway × setting × combination × control) | [pending] MB | `python -I experiments.py e23` |
| `e3-variant/runs.csv.gz`, `web/runs.csv.gz` | < 1 MB each | `python -I e3_variant.py`; `python -I final_export.py` |
| `_shards/` (replicate-level records, gzip JSON lines) | about 0.6 GB | written by every experiment command |

Each script writes to `../results/` relative to its own location. `reproduce.sh` therefore runs a copy of `code/` in a working directory, so the distributed results are never overwritten.

## 4. Running the reproduction

```
./reproduce.sh --quick        # environment, checksums, self-tests, E0, one Morris cell (about 1.5 min)
./reproduce.sh                # everything except the full sensitivity analysis (about [pending] h)
./reproduce.sh --e4-full      # as above, with all of E4a and E4b (about [pending] h)
./reproduce.sh --make-sums    # rewrite SHA256SUMS
```

Options: `--work DIR` (default `./_work`), `--python EXE`, `--reuse-venv`. Each step is logged to `WORK/logs/<step>.log`; a table of steps, outcomes and durations is written to `WORK/status.tsv` and printed at the end. The script stops at the first failing step.

Steps of the default run, in order: environment; checksums of `code/`, `environment/` and `results/` against `SHA256SUMS`; runner self-test; replay check; E0; one Morris cell; E1; E2/E3; approval variant (with `--verify`); secondary analyses (`posthoc.py`); figures; web export; one Sobol cell (or, with `--e4-full`, all of E4a and E4b).

Each regenerated JSON summary is compared with the distributed file by parsing both and comparing every field exactly. The comparison reports the number of differing fields, the largest absolute numeric difference and whether the files are byte-identical. Two fields are excluded by name: `seconds` (wall-clock time, in `e3-variant/summary.json`) and `run_date` (in `web/meta.json`). Figures are compared byte for byte and the outcome is reported, but a difference does not stop the script, because PNG bytes depend on the Matplotlib and FreeType build.

### 4.1 Single sensitivity cells

A complete E4 rerun takes about [pending] h (Section 7). The default run instead recomputes one cell of each analysis exactly as `code/experiments.py` builds it — the same unit-cube sample, the same replicate seeds and the same analysis seed — and compares every index:

- Morris, first pass, cell PW0 × M-A: 1,980 sample points (20 trajectories × 99 points) × 20 replicates; μ* and σ for all 98 parameters, compared with `results/e4-sensitivity/morris.json`.
- Sobol, N = 256, cell PW0 × M-A with the default background: 3,584 sample points × 20 replicates; S1, ST and their confidence intervals for the screened parameters, compared with `results/e4-sensitivity/sobol.json`.

Replicate seeds in E4 depend only on the sample index, not on the cell, so a single cell is an exact subset of the full computation.

### 4.2 The E0 baseline check

`code/baseline.py` locates its two inputs five directory levels above itself, under `_tmp/20261021-aps-delay-attribution/` and `_tmp/20261022-aps-analysis/`, a layout that does not exist inside the package. The code is distributed unchanged. `reproduce.sh` builds a small directory tree (`WORK/e0/`) with that depth, copies `baseline.py` and the two files from `code/data/e0-baseline/` into it, and runs the script there. To run the check by hand, recreate the same layout. E0 does not use `model.py`.

`code/build_inputs.py` and `code/data_prep.py`, which built `code/data/inputs.json` and `code/data/pending76-crashes.csv`, also read source files outside the package (the request-list history and a table of countdown signals and leading pedestrian intervals at the pending crossings). They are distributed to document how the inputs were derived. They are not needed to reproduce any result, and their source files are not included.

## 8. Outputs that cannot be reproduced bit for bit

1. **LLM red team** (`results/llm-redteam/raw-proposals.json`, `checked.json`). A large language model (Claude Sonnet) was used in role-play runs to propose agent behaviours that the rule-based model might omit; a second pass checked each proposal against documentary evidence. These two files are model outputs. They cannot be regenerated identically, because the language model samples its output stochastically and the hosted model changes over time. They were used only to search for omitted mechanisms; no proposal was incorporated into the model, and no statistical result depends on them.
2. **`web/meta.json`** records the date of the export (`run_date`); a rerun writes the current date. All other fields are reproducible.
3. **Figures** (`results/figures/*.png`). The plotted data are reproducible; PNG bytes can differ across Matplotlib and FreeType builds.
4. **Other platforms.** All checks were run on one machine (ARM64, macOS). With the pinned package versions on the same platform, every field is expected to be equal. On other processors or operating systems the last digits of some floating-point averages may differ; conclusions that depend on tolerances or shares are not expected to change. This has not been tested.
