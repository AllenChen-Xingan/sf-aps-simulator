# Reproducibility report

This document states how the results in `results/` are regenerated from the code in `code/`, which checks were run in a clean environment, how long each step takes, and which outputs cannot be reproduced bit for bit. Development, testing and analysis are documented in `docs/TRACE.md` following Grimm et al. (2014); the experimental design is in `docs/experiment-protocol.md`.

## 1. Code identification

| File | SHA-256 |
|---|---|
| `code/model.py` | `6777d8e742dbe414635ab4e4af95092f7abdcb563e1b69d184f56e1e81a114eb` |
| `code/params.py` | `e83c1938cb73657070a3b03c031109c3651cf96bb1903bdd86c00464f9dc49d8` |
| `code/data/inputs.json` | `f37b2885f630e8fe94d4ec9a690968e35b1ab7960f0aef5d141ff1a2218f0401` |
| Combined model fingerprint | `e0f4869e2c32e15f2f3b905a242bcbaa09f7102cf6aaf151acf3e2ac11dff18f` |

The combined fingerprint is the SHA-256 of the three hexadecimal digests above, joined in that order by newline characters (`code/final_export.py`, `code/e3_variant.py`). It is written into `results/e3-variant/summary.json` and `results/web/meta.json`, so each of these result files identifies the model that produced it. Checksums of every file in the package are listed in `SHA256SUMS`.

The clean environment was created with `python3.14 -m venv` and populated only from the lock file. `pip check` reported no broken requirements and `pip freeze` matched the lock file line for line. Installation took 12–15 s with a warm package cache; a cold installation downloads 39 wheels and takes longer, depending on the network.

The simulation itself uses only the Python standard library and NumPy. The other packages are used for sampling and analysis (SALib, EMA Workbench, scikit-learn, pandas) and for figures (Matplotlib).

## 3. Contents and omitted files

The package contains all code, the two model inputs (`code/data/inputs.json`, `code/data/pending76-crashes.csv`), the two inputs of the E0 baseline check (`raw/`), and every summary output. Raw outputs are omitted because of their size; each is regenerated by the command shown (run inside `code/`).

| Omitted file | Size | Regenerated by |
|---|---|---|
| `e1-fit/accepted-sets.json` (parameter combinations accepted by historical screening) | 41 MB | `python -I experiments.py e1` |
| `e3-pathways/runs.csv.gz` (one row per pathway × setting × combination × control) | 67 MB | `python -I experiments.py e23` |
| `e3-variant/runs.csv.gz`, `web/runs.csv.gz` | < 1 MB each | `python -I e3_variant.py`; `python -I final_export.py` |
| `_shards/` (replicate-level records, gzip JSON lines) | about 0.6 GB | written by every experiment command |

Each script writes to `../results/` relative to its own location. `reproduce.sh` therefore runs a copy of `code/` in a working directory, so the distributed results are never overwritten.

## 4. Running the reproduction

```
./reproduce.sh --quick        # environment, checksums, self-tests, E0, one Morris cell (about 1.5 min)
./reproduce.sh                # everything except the full sensitivity analysis (about 1.3 h)
./reproduce.sh --e4-full      # as above, with all of E4a and E4b (about 4 h)
./reproduce.sh --make-sums    # rewrite SHA256SUMS
```

Options: `--work DIR` (default `./_work`), `--python EXE`, `--reuse-venv`. Each step is logged to `WORK/logs/<step>.log`; a table of steps, outcomes and durations is written to `WORK/status.tsv` and printed at the end. The script stops at the first failing step.

Steps of the default run, in order: environment; checksums of `code/`, `environment/` and `results/` against `SHA256SUMS`; runner self-test; replay check; E0; one Morris cell; E1; E2/E3; approval variant (with `--verify`); secondary analyses (`posthoc.py`); figures; web export; one Sobol cell (or, with `--e4-full`, all of E4a and E4b).

Each regenerated JSON summary is compared with the distributed file by parsing both and comparing every field exactly. The comparison reports the number of differing fields, the largest absolute numeric difference and whether the files are byte-identical. Two fields are excluded by name: `seconds` (wall-clock time, in `e3-variant/summary.json`) and `run_date` (in `web/meta.json`). Figures are compared byte for byte and the outcome is reported, but a difference does not stop the script, because PNG bytes depend on the Matplotlib and FreeType build.

### 4.1 Single sensitivity cells

A complete E4 rerun takes about 2.8 h (Section 7). The default run instead recomputes one cell of each analysis exactly as `code/experiments.py` builds it — the same unit-cube sample, the same replicate seeds and the same analysis seed — and compares every index:

- Morris, first pass, cell PW0 × M-A: 1,980 sample points (20 trajectories × 99 points) × 20 replicates; μ* and σ for all 98 parameters, compared with `results/e4-sensitivity/morris.json`.
- Sobol, N = 256, cell PW0 × M-A with the default background: 3,584 sample points × 20 replicates; S1, ST and their confidence intervals for the screened parameters, compared with `results/e4-sensitivity/sobol.json`.

Replicate seeds in E4 depend only on the sample index, not on the cell, so a single cell is an exact subset of the full computation.

### 4.2 Raw inputs (`raw/`)

`code/baseline.py` (the E0 check) reads two files from `raw/` at the package root: `raw/history-long.csv`, the request-list snapshots in long form compiled from the published SFMTA APS request lists, and `raw/baseline-simulation-results.json`, the results of the author's earlier Markov baseline analysis that E0 compares against. Both are distributed, so E0 runs as `python -I code/baseline.py` from the package root; `reproduce.sh` skips E0 only if they are missing. E0 does not use `model.py`.

`code/build_inputs.py` and `code/data_prep.py` built `code/data/inputs.json` and `code/data/pending76-crashes.csv`. They also read from `raw/`: `build_inputs.py` needs `raw/history-long.csv` (distributed), `raw/pending-2026.csv` and `raw/countdown-lpi-pending76.csv`; `data_prep.py` needs the DataSF injury-crash extracts (dataset ubvf-ztfx, pedestrian and all modes, 2015–2025), an intersection coordinate table and `raw/countdown-lpi-pending76.csv`. These source files are not distributed; their origin and fields are described in `docs/data-dictionary.md`. The two scripts document how the model inputs were derived and are not needed to reproduce any result.

## 5. Checks in a clean environment

All checks were run on a copy of `code/` in a new virtual environment, with outputs written to a separate directory.

| Check | Command (in `code/` unless stated) | Time | Result |
|---|---|---|---|
| Checksums | `shasum -a 256` | < 1 s | `model.py`, `params.py`, `data/inputs.json` and the combined fingerprint equal the values in Section 1 |
| Runner self-test | `python -I runner.py --selftest` | 2 s | 168 tasks × 3 replicates; one process and 8 processes give identical output: True |
| Replay and rule checks | `python -I replay_check.py` | 10 s | Replay mismatches 0; installation reconciliation mismatches 0; all targeted rule tests pass |
| E0 baseline | `python -I code/baseline.py` (from the package root) | 3 s | Output byte-identical to `results/e0-baseline-check.json`: median 20 installations, 10th–90th percentile 13–28; reference 20 and 13–27; within tolerance |
| Approval switch off reproduces the main E3 runs | `python -I e3_variant.py --verify` | 6 s (part of the variant run) | 108 rebuilt tasks (PW0, PW4, PW5 × 6 settings × 2 controls × 3 combinations) vs the rows of `e3-pathways/runs.csv.gz`: 0 field differences |
| Quick reproduction from a new environment | `./reproduce.sh --quick` (package root) | 71 s | All 10 steps pass: environment, checksums, both self-tests, E0 and one Morris cell; the Morris cell is byte-identical to the corresponding entries of `results/e4-sensitivity/morris.json` |
| Single Sobol cell | `e4_cell.py` as called by `reproduce.sh` | 67 s | 3,584 sample points × 20 replicates; byte-identical to the corresponding entries of `results/e4-sensitivity/sobol.json` |

## 6. Main experiments

All experiments were run with master seed 146, 20 replicates per parameter combination, and the parameter combinations and replicate seeds defined in `docs/experiment-protocol.md`.

| Experiment | Command (in `code/`) | Tasks (× 20 replicates) | Time | Output |
|---|---|---|---|---|
| E1 historical screening | `experiments.py e1` | 86,400 (48 months each) | 17 min | `results/e1-fit/fit-table.json` |
| E2/E3 conditions for funding and pathway comparison, with the zero-direct-effect control | `experiments.py e23` | 84,000 (120 months each) | 53 min | `results/e2-prim/prim.json`, `results/e3-pathways/robustness.json` |
| Approval variant | `e3_variant.py --verify` | 12,036 (combinations without a standing line; PW4, PW5 × 6 settings × 2 controls) | 6 min | `results/e3-variant/summary.json` |
| Secondary analyses | `posthoc.py` | — (no simulation) | 15 s | `results/e3-pathways/posthoc.json` |
| Figures | `figures.py` | — | 2 s | `results/figures/` |
| Web export | `final_export.py` | — | 24 s | `results/web/` |
| E4a Morris, two passes | `experiments.py e4a` | 83,160 per pass | 77 min (both passes) | `results/e4-sensitivity/morris.json` |
| E4b Sobol, N = 256 and 512, with background checks | `experiments.py e4b` | 78,848 (N = 256: 22 cells × 3,584) and 100,352 (N = 512: 14 cells × 7,168) | about 88 min of computation (see Section 7) | `results/e4-sensitivity/sobol.json` |

The historical segment of the model (runs starting in July 2022, used only by E1) is unaffected by the model changes recorded in `docs/TRACE.md`: rerunning E1 with the final code reproduced all 86,400 task records, the fit table and the accepted parameter combinations byte for byte.

Checks completed against the distributed results: the quick reproduction from a new environment passed every step in 71 s; the single Morris and Sobol cells were byte-identical to the corresponding entries of `results/e4-sensitivity/`; the E1 rerun was byte-identical for all 86,400 task records; and with the approval switch off, 108 rebuilt main-run tasks showed no field differences. A full rerun of the default mode with field-by-field comparison is reported in Section 6.1.

## 7. Time and hardware requirements

The totals below are sums of the step durations measured on the machine in Section 2 (Sections 5 and 6).

| Mode | Main components | Total |
|---|---|---|
| `--quick` | environment, checks, E0, one Morris cell | 71 s (measured) |
| default | quick steps, E1 (17 min), E2/E3 (53 min), approval variant (6 min), secondary analyses, figures, web export, one Sobol cell | about 1.3 h |
| `--e4-full` | default without the single Sobol cell, plus E4a (77 min) and E4b (about 88 min) | about 4 h |

The E4b duration is the computation time, estimated from the intervals between consecutive output shards; the run was interrupted by periods of system sleep, so its wall-clock time is not informative.

Memory use is modest (under 1 GB per worker process). Raw outputs occupy about 0.7 GB of disk. On a machine with fewer cores, time scales roughly inversely with the number of worker processes; results do not depend on that number (Section 5, runner self-test).

## 8. Outputs that cannot be reproduced bit for bit

1. **LLM red team** (`results/llm-redteam/raw-proposals.json`, `checked.json`). A large language model (Claude Sonnet) was used in role-play runs to propose agent behaviours that the rule-based model might omit; a second pass checked each proposal against documentary evidence. These two files are model outputs. They cannot be regenerated identically, because the language model samples its output stochastically and the hosted model changes over time. They were used only to search for omitted mechanisms; no proposal was incorporated into the model, and no statistical result depends on them.
2. **`web/meta.json`** records the date of the export (`run_date`); a rerun writes the current date. All other fields are reproducible.
3. **Figures** (`results/figures/*.png`). The plotted data are reproducible; PNG bytes can differ across Matplotlib and FreeType builds.
4. **Other platforms.** All checks were run on one machine (ARM64, macOS). With the pinned package versions on the same platform, every field is expected to be equal. On other processors or operating systems the last digits of some floating-point averages may differ; conclusions that depend on tolerances or shares are not expected to change. This has not been tested.
